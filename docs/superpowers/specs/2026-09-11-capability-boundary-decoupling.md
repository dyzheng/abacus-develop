## 4. 分析（Analysis）

1. **为什么是"能力边界"而非"bug"**：脱钩不破坏 CDFT 共轭关系的严格性——约束
   确实作用在 `q` 的共轭量上、`q` 也确实到靶；问题是 `q` 与用户真正想要的物理量
   （d 局域矩）不是同一个可观测量。把它写进边界表（而不是 bug 表）是对"基组无关
   卖点"付代价的最诚实记账，也直接支撑阶段 B 立项评审里"适用范围"那一条。
2. **两条盲区为何必须与 L14 同页登记**：二者是同一类"读数可信度"风险的两端——
   L14 是"读对了但读的不是那个量"，L15 是"读到的可能是另一个解"。II-1 的两类
   事故（换态被记成 CONVERGED、约束动的是 Becke 矩而非 d 矩）恰好各占一端，
   用户侧的对策也因此必须成对给出（并读 `onsite=` + 开守卫查 `final status`）。
3. **盲区分级**：①（能量向上换态）与 ②（非收敛不判）是真正的盲区；容差量级
   选择是使用纪律而非盲区，故在 L15 里以"另："分隔，与 spec §4.6 的三条对齐。
4. **不新增能力声明**：本轮只登记限制，把 I-1 MgO 的正向判决（线性区 ≥ ±0.8 e）
   留给第 6 项的写回轮，避免一份文档同时承担"扩适用域"与"收适用域"两类修改。
