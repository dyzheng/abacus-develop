# 带交叉与极化分支唯一性分析

> 日期: 2026-07-15  
> 问题: 带交叉是否是分支选择失效的根源？能否只考虑费米面附近的价带？

---

## 一、逐点分析

### 1.1 "带交叉是关键数值发散" — ✅ 正确

带交叉 (两个 k 点间特征值相位差 < ε) 是 Hungarian 匹配不确定性的**唯一根源**:

```
正常情况: evals_prev = {0.3, 1.8} rad, evals_new = {0.35, 1.75}
  cost = [[0.05, 1.45],    → Hungarian: 0→0, 1→1 (确定)
          [1.50, 0.05]]

带交叉:    evals_prev = {0.30, 0.31} rad, evals_new = {0.35, 0.34}
  cost = [[0.05, 0.04],    → Hungarian: 二义性 (0.05+0.03 = 0.04+0.04)
          [0.05, 0.03]]
```

cost 矩阵中 relevant entries 几乎相等 → 匹配的全局最优解在 ±ε 范围内部署 → 微小浮点差异 (不同编译器, 不同优化等级) 选不同匹配 → gamma_unwrapped 差 2π → 全链路发散。

**当前代码**: **无带交叉检测**。Hungarian 算法只是让匹配"确定"而非"正确"——它排除随机性但无法纠正物理上不唯一的匹配。

### 1.2 带交叉的极化是否需要考虑 — ⚠️ 看情况

**关键: 单带贡献不确定, 但总贡献不变:**

```
带 n 和 m 在 k_j 处交叉
gamma_unwrapped[n] + gamma_unwrapped[m] = const (gauge invariant)
但 gamma_unwrapped[n] 和 gamma_unwrapped[m] 各自不确定
```

per-atom gamma: `γ_I = Σ_k w_I_k × gamma_unwrapped[k]`

| 场景 | w_I_n ≈ w_I_m | w_I_n ≠ w_I_m |
|------|:---:|:---:|
| 交叉影响 | **无** — 交换时 γ_I 不变 | **有** — 交换时 γ_I 跳变 |
| BN 实例 | 带 0 和 1 (成键带, w≈0.03-0.06) | 带 1 和带 2 (w≈0.06 vs 1.63) |

**BN 实际情况**: 带 2 (N 孤对电子, w_sum=1.63) 远大于其他带。带 2 不与任何带交叉 (孤立于其他占据带)。带 0 和 1 可能会交叉, 但它们的 w_In 相似 → 交叉对 per-atom γ 影响很小。

**结论: BN 的带交叉对 per-atom 极化影响微弱。H₂O 和 BTO 可能有更严重的带交叉需要处理。**

### 1.3 "只考虑费米面附近的价带" — ⚠️ 在当前不适用

| 体系 | nocc | 第 nocc 个带 | w_sum (最后一个带) |
|------|:---:|------|:---:|
| BN | 4 | 反键带 (above EF) | 0.016 |
| H₂O | 4 | 反键带 | 很小 |
| BTO (5原子) | 12+ | — | — |

BN 的带 3 (反键) 贡献微乎其微 (w_sum=0.016/4 ≈ 0.4%)。**丢弃带 3 对极化影响 <1%**。

但带 0-2 的 w_sum 为 0.034+0.061+1.625=1.72。如果只取 "最靠近 EF 的带" (带 2), 会丢失 0.095/1.72 ≈ 5.5% 的极化。

**对于具有深能级芯态的大体系 (BTO, >50 个占据带), 确实可以只考虑费米面附近 ~10-20 个价带。但当前 BN/H₂O 的 4 个占据带全部需要。**

**更关键的问题**: 当前代码 `n_dim = nocc_use` 直接等于 `ceil(nelec/DEGSPIN)`, 无法缩减。需要添加 `deltap_nbands` 参数控制 Wannier 子空间大小。

### 1.4 带交叉检测的可行方案

**方案 1: 最小相位间隔检测**

```cpp
double min_gap = 1e10;
for (int n = 0; n < n_dim-1; ++n)
    for (int m = n+1; m < n_dim; ++m)
        min_gap = min(min_gap, abs(arg(evals_j[n]/evals_j[m])));
if (min_gap < crossing_threshold)  // e.g. 0.01 rad
    mark_as_crossing(j);
```

简单但只检测同一 k 点的简并, 不能检测"接近但未交"的情况。

**方案 2: cost 矩阵二义性检测**

```cpp
// 在 Hungarian 匹配后检查 cost 差异
double best_cost = total_cost[matched];
double alt_cost = total_cost[swapped];
if (abs(best_cost - alt_cost) < 1e-6)
    mark_as_ambiguous(n, m);  // 带 n 和 m 的匹配不可靠
```

只检测 Hungarian 层面的 ambiguity。不需要额外计算。

**方案 3: 合并跟踪 (Merge tracking)**

当检测到交叉/ambiguous 时, 将两个带合并为一个"复合带":

```
gamma_unwrapped_merged = gamma_prev[n] + gamma_prev[m]  (和不变)
w_In_merged = w_In[n] + w_In[m]                         (权重合并)
```

合并后只有 n_dim-1 个独立的"带", Hungarian 匹配问题降维。
交叉过后 (下个 k 点), 尝试重新分解 (如果有足够信息分离), 或保持合并到最后。

**推荐: 方案 2 + 方案 3 组合。**

## 二、BN 测试数据中的带交叉证据

从 BN 2×2×2 测试输出:

```
n=0 raw_sum=0.034, n=1 raw_sum=0.061, n=2 raw_sum=1.625, n=3 raw_sum=0.016
```

四个带的 SMO 权重层次分明: 带 2 孤立 (1.63), 带 0/1 接近 (0.03-0.06), 带 3 可忽略 (0.016)。

从 cross-string diagnostic:

| 方向 | σ(B) | σ(N) | BRANCH |
|------|:---:|:---:|:---:|
| 同一次 run | ~3e-3 | ~3e-3 | OK |

σ 很小 → **在同一 run 内不存在跨 string 的带交叉**。带交叉如果存在, 应表现为 σ 在带 0 和 1 之间跳变 (因为它们 w_In 不同)。

**当前 BN 没有带交叉。核心问题不是带交叉, 而是不同 λ 值的 Hungarian 匹配在无交叉的正常情况下也不一致 (因为 O_j 矩阵微变)。**

---

## 三、真正的问题: 无交叉时的匹配不确定性

即使没有带交叉 (min_gap >> ε), 不同 λ 值运行也会产生不同的 Hungarian 匹配:

```
λ=0 的 O_j: C†(k)·S(dk)·C(k)     →  evals = {0.30, 0.31, 1.80, 2.90}
λ=0.05 的 O_j: C†(k)·S(dk)·C'(k) →  evals'= {0.29, 0.32, 1.79, 2.89}
```

cost 矩阵非常相似, 匹配结果相同 → gamma_unwrapped 一致 → 没问题。

但 λ=0 和 λ=0.05 的 **SCF 路径不同** → 波函数 C 不同 → O_j 不同 → evals 不同。这在 cost 差 > ε 时不是问题 (**确定匹配**)。只有当 λ 的变化恰好将两个 eval 推开/拉近到 cost 差 < ε 时才触发不确定性。

**关键**: 当前 BN 没有带交叉, λ sweep 的振荡来自别处 (可能是 SCF 收敛路径差异导致 prev_gamma 初始化不同, 或 W_prev_ 的跨 run 加载有 bug)。

---

## 四、结论

| 质疑 | 结论 |
|------|------|
| 带交叉是关键发散 | ✅ 正确, 但 BN 当前无带交叉。应加检测以防未来体系出问题 |
| 交叉带的极化不需考虑 | ⚠️ 单带贡献不确定, 但总贡献不变。应合并跟踪而非忽略 |
| 只考虑费米面价带 | ✅ 对 BN 4 带全部需要; 对大体系 (>20 带) 可缩减, 但需加参数 |
| 交叉检测实现 | 方案 2 (cost 二义性) + 方案 3 (合并跟踪) 最可行 |
| 当前 λ sweep 振荡根源 | 不是带交叉 — 需排查 SCF 路径差异和 W_prev_ 加载 |
