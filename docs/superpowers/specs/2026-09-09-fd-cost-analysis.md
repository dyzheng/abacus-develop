# FD 验证计算成本分析：不是算例问题，不是算法缺陷——是构建类型 + 验证处方 + 协议冗余的叠加

> 起因：V1 力 FD 全 18 腿估计 ~8.7 h（87 min/wave × 6），用户质疑成本是否合理。
> 方法：从现有日志提取成本结构 + 构建配置核查。结论先行：**约束算法本身的开销 <1%（实测），成本由三个可分离因素叠加，其中最大的一个（debug 构建）此前无人指出——评审链也有责任。**

## 1. 成本结构实测（V1 冒烟 base，R7 设置 nspin=2）

53 次 SCF 迭代的计时表：

| 项 | 时间 | 占比 |
|---|---|---|
| HSolverPW 对角化（DiagoCG，106 次调用 × 11.1 s） | 1323 s | **99.9%** |
| ElecStatePW psiToRho | 48 s | 3% |
| **约束注入+读数（inject/observe）** | **计时表中不出现** | **<1%** |

**约束算法的渐进开销可忽略不计**——全部时间花在 KS 对角化上（npwx=96146 平面波）。"算法有严重效率缺陷"不成立。

## 2. 三个成本因素（按可修复收益排序）

### 因素 A（最大）：验证跑全部在用 debug（-O0）二进制
`build/CMakeCache.txt`：CMAKE_BUILD_TYPE=debug、CMAKE_CXX_FLAGS_DEBUG=-g（即 -O0）。
对角化是 BLAS/循环密集代码，-O0 vs -O3 典型差 **3–10×**。23m42s 的 base 在 release 下预期 ~4–8 min；18 腿从 ~8.7 h 降到 ~1.5–3 h。**这是单项收益最大的修复，且零代码改动。**（build_asan 是 -O3 但带 ASAN 插桩，同样慢，不适用。）

### 因素 B：R7 网格处方是刻意的验证成本，非缺陷
ecutwfc=100/ecutrho=400 → npwx=96k（生产 ecutwfc=20 的 ~11× 基组、迭代成本 ~10–30×）。
该处方来自 egg-box 噪声标定（低网格噪声达判据一半），是 FD 判决的必要条件——
**但可以用"网格-噪声标定"优化**：先在 ecutwfc=60/ecutrho=240 跑一条轴测噪声，
若噪声 ≪ 判据/3 则降档验收，省 3–4×。生产算例（ecutwfc=20）单次 SCF 是分钟级以内，与验证成本无关。

### 因素 C：FD 腿无热启动（协议冗余，非算法缺陷）
每腿从 μ=0 重优化（step_max=0.05 < |μ*|≈0.072）→ 每腿 2 外步 = 2× SCF。
而 fixed-μ 腿与重优化-μ 腿的 FD 已证**逐位同值**（SCC 修复文档，PW/LCAO 双证）→
换 fixed-μ 协议省 **50%** 腿成本，零代码改动（开关已存在）。

## 3. 非因素排除

- **算例不合理？否**——H₂O 小分子正是 FD 验证该用的最便宜体系；问题不在体系选择；
- **约束算法效率缺陷？否**——§1 实测注入/读数 <1%；外环迭代次数（单约束 3–6 步）与 CDFT 标准行为一致；
- **SCF 本身病态？否**——53 迭代/3 外步的收敛行为正常，scft_thr=1e-8 的紧收敛是 FD 处方要求。

## 4. 建议行动

1. **立即（V1 当前批次之后）**：建 release（-O3）构建专用于重型验证跑。
   V1 当前批次已在 debug 上跑了 wave 1–2，腿间可比性要求同一二进制——**本批用 debug 跑完**；
   **V2 起用 release**，并跑 1 条对照腿验证 debug/release 的 FD 结论一致
   （FD 是差分量，对绝对值末位差异不敏感，预期一致；result.ref 类绝对值对拍必须在同一构建类型下重生成）。
2. **V2 起**：fixed-μ 协议（省 50%）+ 网格噪声标定（可能再省 3–4×）——叠加 release 后，
   混合 FD 总成本预估从 ~16 h 降到 **~1–2 h**。
3. **纪律新增**：重型验证跑的 spec 必须记录构建类型；评审时把"构建类型是否匹配跑的重型程度"列为检查项。
   （透明性此前已有——spec 写了"debug 构建"——但包括评审在内的所有人都没把 debug 当成本因素提出，教训入档。）
