## 一、方案做对了什么

1. **根因定位准确**：把"混合约束不可表达"归因到 `constraint_type`/`DensityChannel` 的 run 级全局性——与开发者文档 §6.2 风险表及 2026-08-31 混合约束实测（charge_spin 被守卫拒绝）完全一致。`ChannelProfile(read_up, read_dn, inj_up, inj_dn)` 是干净的泛化：charge=(+1,+1,+μ,+μ)、spin=(+1,−1,+μ,−μ) 统一表达，无特判分支。
2. **建筑不变量全部保留**：单权重实例（观测量==注入算符）、无状态核、仅 v_eff/rho 耦合——与我开发者文档的结构性事实一致，改动面评估（M7/M1/M2/M3a 低、M8 中、M4 高）现实。
3. **纪律继承完整**：生命周期势存活检查扩展到新通道（§5）、冻密度响应禁用（§3.4 的 T-7″ 警告）、偶极 delta 强制 + z₀ 固定（∂w/∂R=0 的正确前提）、体相极化红线（Berry 走 DeltaP，§6）——全部与评审链结论吻合。
4. **偶极 R5 高危提醒保留**（§4.3），没有把"统一框架"误读为"偶极和电荷一样好做"。

## 二、必须修正的问题

### P1【内部矛盾】47 步基准不会被方案的块结构解决
方案 §3.3 以"近共线对（47 步基准）"作为 Broyden 的核心动机，但其块设计是**按 kind 分块**（块内对角 secant、块间 Broyden）。而 47 步实测案例是 **spin+spin 同 kind 双约束**（O +0.1 / H1 −0.05 μB，2026-08-31-mixed-charge-spin-test）——按方案自己的规则，它落在**块内**，仍走对角 secant，**仍将慢收敛**。该案例的病根不是"跨类型硬×软耦合"，而是 **Jacobian 近奇异**（两约束近共线，μ_H1≈0——H1 靶点几乎被 O 约束顺带满足）。对症的方案是：块内近共线检测（约束合并/奇异值截断）或**块内也允许 Broyden**——无论哪种，方案的"块内对角够用"论断与其头号动机案例直接冲突。必须修正：要么改块结构（按耦合测量动态分组），要么把 47 步案例从 Broyden 动机中删除并单列"近共线对处理"。

### P2【排序】2.6 判决门未闭合，不能动架构
LCAO 18 腿全量、力矩 FD、PW≡LCAO、2.7 判决门仍在队列中。架构级改动会使 2.6 的验收基线失效（钩子、channel、schema 全在动）。**硬要求：阶段 A 代码工作必须在 2.6 闭合后启动**；闭合前只允许做 schema/接口的纸面设计。混合约束本身（原 Task 2.4.1）历来被定为非阻塞项，本方案整体继承此定位，不应插队到判决门之前。

### P3【未验证主张】"跨类型耦合强（电荷↔偶极是硬×软通道）"无实测
方案 §3.3 标注"实测（R3）"，但仓库内的实测只有**同类型**弱耦合（2026-07-21 H₂O 约束 Hessian 非对角 ~0.1%，且那是 DeltaP γ 语境）；电荷↔偶极耦合**从未被测量**（偶极通道尚不存在）。Broyden 的立项应改为**测量驱动**：阶段 A 落地后先实测混合场景的 Jacobian 条件数/收敛步数，超阈值再启动阶段 B。这同时解决 YAGNI 顾虑——效率三层（3.2/3.3/3.4）中 3.3/3.4 目前只有推测性需求。

### P4【细节风险】松-紧 SCF 调度需要 Q 噪声预算
§3.2 的松阈值早停会抬高 Q(μ) 读数噪声。历史教训（2026-07-12-scf-convergence-verified）：观测量收敛条件可比能量严格得多——虽然本框架的 Q=∫w·ρ 是密度量（不像 Wilson 相位那样对 ψ 敏感），风险较低，但 secant/Broyden 的 κ 估计是 Q 的差商，对噪声敏感。**要求**：调度表配一条硬断言——松档下 Q 的轮间噪声 ≪ constraint_thr/10，否则自动退回紧档；且力求值前必须处于紧档（方案已含末尾紧 SCF，需在文档写死）。

### P5【操作性缺口】schema 迁移与 result.ref 链
约束列表 schema 破坏现有 3 个注册用例的靶文件格式。阶段 A 必须包含：旧格式迁移（或向后兼容一个版本 + deprecation WARNING）+ 3 用例 result.ref 重生成协议 + 文档（用户手册 §3）同步。

## 四、结论

方案的架构判断（90% 骨架就绪、根因唯一、ChannelProfile 泛化）经核实成立，纪律继承完整，是一份合格的演进方向文档。但它把"用户要的混合约束"（小、确定）和"推测的效率优化"（中、未测量）捆在一起，且效率层的核心案例与其结构设计自相矛盾（P1）。**建议：2.6 闭合后按修订版阶段 A 实施混合约束；阶段 B/C 以测量报告为立项前提。**
